# Giliran mulai ujian XII → XI → X

Siswa login dan memilih **Mulai ujian** seperti biasa. XII boleh mulai terlebih dahulu. XI dibuka setelah 300 siswa unik XII berhasil mulai **atau 3 menit tahap XII berlalu**, mana yang lebih dahulu. X dibuka setelah 300 siswa unik XI berhasil mulai **atau 3 menit tahap XI berlalu**. Tingkat sebelumnya tetap bisa mulai. Jumlah ini kumulatif selama sesi, bukan jumlah siswa yang harus terus aktif bersamaan.

Timer pertama dimulai pada pengecekan giliran atau request mulai siswa pertama di sesi tersebut. Melihat status dari panel admin tidak memulai timer. Setiap tingkat yang dibuka memulai jendela 3 menit untuk tingkat berikutnya. Karena itu, bila tidak ada tingkat yang memenuhi kuota, XI terbuka pada menit ke-3 dan X pada menit ke-6 sejak aktivitas siswa pertama. Polling, refresh, login ulang, serta kedatangan siswa baru tidak mengulang waktu tunggu. Penghitungan menggunakan jam Redis bersama semua instance API. Bila polling berhenti lebih dari enam menit, pengecekan berikutnya langsung mengejar kedua jendela yang sudah berakhir.

Hitungan dibagi per tanggal mulai dalam zona `EXAM_ADMISSION_TIMEZONE` (default `Asia/Jakarta`), nomor sesi, tahun ajaran, dan semester. Paket ujian tiap tingkat memakai hitungan bersama apabila keempat nilai itu sama. Memilih paket lain atau refresh pada sesi yang sama tidak menghitung siswa dua kali. Jam mulai paket boleh berbeda selama tanggal dan nomor sesinya sama; kelayakan jadwal masing-masing paket tetap diperiksa.

Saat menunggu, siswa melihat animasi dan pesan **“Silakan tunggu, sesi Anda akan segera dimulai...”**. Client memeriksa giliran setiap 5–10 detik, lalu memberi jitter 0–10 detik ketika tingkat dibuka. Pemeriksaan menggunakan tiket bertanda tangan yang terikat pada siswa dan ujian serta Redis, tanpa query DB setiap polling. Timer ujian baru dibuat ketika request mulai benar-benar diizinkan, dan tetap dibatasi waktu akhir jadwal ujian.

**Siswa terlambat masuk langsung:** tombol Mulai memeriksa status sebelum menampilkan ruang tunggu. Jika tingkat siswa sudah dibuka, client langsung memanggil endpoint mulai, tanpa tampilan ruang tunggu atau jitter pembukaan gelombang. Pembukaan bersifat satu arah dan tetap berlaku sepanjang sesi meskipun jumlah siswa aktif kemudian berkurang atau siswa lain sudah selesai.

Server juga menolak request mulai langsung dari tingkat yang belum dibuka dengan HTTP 425. Redis Lua menjalankan perubahan tingkat serta pencatatan siswa unik secara atomic. Hitungan dicatat sesudah transaksi pembuatan attempt berhasil COMMIT, dan `SADD` mencegah penambahan ganda ketika respons diulang atau sesi dilanjutkan. Sesi yang sudah ada dapat dilanjutkan tanpa mengantre ulang, termasuk saat Redis sedang terputus; pencatatan hitungannya dicoba lagi pada resume berikutnya. Redis menyimpan state serta set siswa pada `arena:admission:{group}:state` dan `:XII`, `:XI`, `:X`, dengan TTL default 48 jam sejak aktivitas terakhir.

Jika petugas perlu membuka lebih awal, admin membuka **Pengaturan Sistem → Giliran mulai ujian**, memilih salah satu jadwal dalam sesi itu, menekan **Perbarui status**, lalu **Buka tingkat berikutnya**. Tombol yang sama dipakai lagi untuk tingkat berikutnya. Operasi memakai pemeriksaan tingkat sebelumnya sehingga pengulangan request tidak melompati dua tingkat, dan dicatat di audit log. Peserta kurang dari 300 tidak memerlukan tindakan admin karena batas 3 menit akan membuka tingkat berikutnya otomatis.

Konfigurasi lokal tersedia di `.env.example`: `EXAM_GRADE_ADMISSION_ENABLED=true`, `EXAM_GRADE_ADMISSION_THRESHOLD=300`, `EXAM_GRADE_ADMISSION_MAX_WAIT_SECONDS=180`, `EXAM_GRADE_ADMISSION_TTL_SECONDS=172800`, `EXAM_ADMISSION_TIMEZONE=Asia/Jakarta`. Ambang dan durasi disimpan sekali per sesi sehingga semua proses memakai nilai yang sama; perubahan konfigurasi berlaku pada sesi baru. Pada state lama yang belum menyimpan timer, waktu dimulai saat aktivitas siswa pertama setelah pembaruan, dan tingkat yang sudah terbuka tetap terbuka. Redis diperlukan saat fitur aktif; Redis yang belum siap membuat mulai baru menunggu, bukan melewati prioritas. Gunakan AOF/persistensi Redis sesuai rencana infra. Jika Redis kehilangan data, admin perlu meninjau keadaan attempt di DB dan membuka kembali tingkat yang semestinya melalui kontrol manual. Tidak ada reset otomatis atau penghapusan data Redis oleh fitur ini.

Endpoint siswa: `GET /api/student/exams/:id/admission?ticket=...`; tiket diberikan pada daftar ujian siswa. Endpoint admin: `GET /api/admin/exam-admission?exam_id=...` dan `POST /api/admin/exam-admission/advance` dengan body `{exam_id, expected_grade}`. Hak admin dan CSRF diperiksa untuk perubahan.

Tes `apps/api/tests/exam-admission.test.mjs` mencakup scope tanggal/sesi, batas 299/300, batas 179/180 detik, timer tidak diulang oleh polling/pendatang baru, dua tahap kedaluwarsa tanpa polling, siswa terlambat tetap diizinkan, kompatibilitas state lama, request serentak dan idempotensi hitungan, pembukaan manual idempotent, isolasi sesi, penolakan tiket palsu, Redis tidak tersedia, serta penolakan mulai XI sebelum pembacaan/penulisan soal. Tes Lua telah dijalankan pada Redis lokal sementara di port terpisah; DB aplikasi dan server remote tidak diakses.
