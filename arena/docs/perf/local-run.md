# Uji lokal alur ujian

Prasyarat: Node >=22, Docker Compose, k6. Tidak ada pengujian terhadap staging atau production dari panduan ini.

1. Dari `arena/`, jalankan `docker compose -f docker-compose.dev.yml up -d` (tanpa `down -v`). Buat `arena/.env` dari `.env.example` dengan secret acak **khusus lokal**; sesuaikan `DATABASE_URL` ke port 3308 dan `REDIS_URL` ke 6379.
2. Pada DB lokal baru, jalankan `npm install`, `node --env-file=.env scripts/migrate-local.mjs`, `npm run build -w @arena/api`, lalu `node --env-file=.env scripts/seed-perf-local.mjs`. Saat antrean tingkat aktif (default), skrip membuat 340 siswa XII, 340 XI, 335 X, tiga paket masing-masing 40 soal, serta tiket giliran di `tmp/perf-tokens.json` yang diabaikan Git. Scope tahun ajaran dummy berbeda pada setiap run agar hitungan Redis run sebelumnya tidak terbawa. Dengan `EXAM_GRADE_ADMISSION_ENABLED=false` pada seed dan API, skrip tetap menyediakan varian lama satu paket X untuk seluruh siswa. Jangan menjalankan migrasi inti berulang pada DB yang sudah berisi tabel.
3. Jalankan `node --env-file=.env apps/api/dist/server.js`, lalu pada terminal lain `node --env-file=.env scripts/warmup-exam-local.mjs EXAM_ID` untuk setiap paket tepat sebelum gelombang. ID ujian dicetak oleh seed. Cache Redis memiliki TTL dua detik, sehingga warmup jauh sebelum ujian tidak memberi manfaat.
4. Jalankan `k6 run -e BASE_URL=http://127.0.0.1:3001 tests/k6/exam-flow.js` (skrip membaca `tmp/perf-tokens.json` relatif terhadap berkas skrip). Fixture tingkat membuat VU menunggu giliran melalui polling murah sebelum mulai. Untuk klik serentak tanpa jitter setelah pembukaan gunakan `-e MODE=simultaneous`; untuk 0,3 detik per jawaban gunakan `-e STRESS=true`. `-e LEGACY=true` mengukur rute PUT lama. Gunakan exam baru dari seed untuk setiap run agar attempt lama tidak menghasilkan 409. Untuk perbandingan kode lama yang belum mendukung tiket giliran, nonaktifkan fitur pada seed dan API.
5. Setelah semua VU selesai, jalankan `node --env-file=.env scripts/verify-perf-local.mjs`. Cocokkan jumlah `exam_results` dengan jumlah submit sukses dari k6; skrip memerlukan 1.015 hasil secara default dan memeriksa duplikat/hasil yang hilang menurut status attempt. Untuk run VU lebih kecil, atur `EXPECTED_FINISHES` sesuai target run. Simpan ringkasan k6, CPU, event loop, pool, serta query/lock DB di `docs/perf/` dengan tanggal run.

Pada mesin yang dipakai untuk perubahan ini, Docker/k6 tidak terpasang dan Node Laragon adalah v18.8.0. Karena itu angka baseline/after dan klaim kapasitas belum tersedia.
